# 安全与隐私

- 版本：1.0.0
- 最后更新：2026-11-05

## 总原则

反馈系统会拿到用户写的文字与截图，所以默认假设**它会接触到敏感内容**。
下面每一条都是这个默认假设的推论。

## 客户端

### APK 里没有服务端凭据

- `appId` 是公开标识，用来区分应用，**不是凭据**；
- 提交接口不需要任何客户端密钥；
- APK 里只有 `appId` 与服务地址；
- 管理员密码、服务端密钥只存在于服务器的环境变量里。

这与「反馈通道是飞书 webhook」的做法不同：webhook 地址本身就是写入凭据，
随 APK 分发可被提取，只能靠飞书侧的签名校验兜底。

### 不采集的东西

客户端**不会**采集：

- IMEI、手机序列号、MAC 地址；
- GPS 位置；
- 账号、密码、Cookie、Token；
- Wi-Fi 密码；
- 任何其它系统标识符。

自动附带的只有：App 名称与版本、build 号、SDK 版本、Android 版本、
API Level、制造商、型号、系统语言。

反馈页面上会明确告诉用户附带了什么。

### 截图

- 用 Android Photo Picker，**不申请**整个相册的读取权限；
- 只有用户主动选择才会读取；
- 最多 3 张，单张压缩后 ≤ 2 MB，最长边 ≤ 2048 px；
- 重新编码为 JPEG，**这一步会剥掉 EXIF**（原图里的位置与设备信息不会离开手机）；
- 不自动截取整个 App 屏幕。

### 诊断信息

- 第一版不自动收集 logcat；
- SDK 提供一个可选的 `diagnosticProvider`，**只有用户主动勾选时才会调用**；
- 过滤敏感内容是**宿主的责任**——SDK 不知道宿主的哪些数据是敏感的。

宿主应该采用「白名单」而不是「黑名单」：只放行确定安全的状态类事件，
其余整行丢弃。整行丢弃不会留下「这里原来有个账号」的痕迹。

## 服务端

### 传输

- 全程 HTTPS（Caddy 自动签发与续期）；
- FastAPI 的端口不发布到宿主机，只有 Caddy 能访问。

### 限流

- 每 `(appId, 客户端 IP)` 每小时 10 条（可配置）；
- 客户端 IP **只存哈希**（加盐 SHA-256），数据库里看不到原始地址；
- 登录接口另有独立的限流。

### 附件

- 按**魔数**判定格式，不信 MIME 与扩展名；
- 只接受 JPEG / PNG / WebP；
- 单张 ≤ 2 MB，最多 3 张，请求体 ≤ 12 MB；
- 存在私有目录，**文件名由服务端随机生成**，客户端不能指定路径；
- 显示用的原始文件名会被清洗（去路径分隔符与控制字符）；
- 只能通过**带管理员会话**的接口下载，不在公开静态目录里。

### 管理后台

- 密码用 Argon2id 哈希；
- 首次启动时从环境变量创建管理员账号，之后不再读取；
- 会话 token 存哈希，Cookie 是 HttpOnly + Secure + SameSite=Lax；
- 改状态、加备注需要 CSRF token；
- 没有公开注册入口；
- 管理接口对匿名用户一律 401。

### 幂等

`(app_id, submission_id)` 唯一。这既是可用性措施，也是安全措施：
恶意客户端用同一个 `submissionId` 疯狂重试，只会在库里留下一条记录，
不能靠重试把后台刷满。

## 日志

- **不记录**反馈正文、联系方式、诊断摘要；
- 日志只记：反馈 id、应用、类型、附件数、HTTP 状态；
- 访问日志里不记查询串（后台搜索词可能含用户输入）；
- Caddy 的访问日志同样不记查询串。

## 数据保护

服务端**不会**自动接收：

- 用户的照片原件（除非用户主动在反馈里挑了截图）；
- 应用的数据库、模型文件、向量索引；
- 完整聊天记录、Prompt、模型上下文、工具调用参数。

这些都要宿主自己决定要不要附带，而且必须自己脱敏。

## 已知取舍

| 取舍 | 原因 | 缓解 |
|---|---|---|
| 提交接口匿名 | 反馈不该要求注册 | 限流 + `submissionId` 去重 |
| 附件公开可读性差（需登录） | 截图可能含个人信息 | 只能管理员下载 |
| 服务端保存反馈原文 | 作者要能看到问题描述 | 只保存在自有服务器，不外传第三方 |
| 短周期证书（6 天） | IP 证书的强制要求 | Caddy 自动续期 |
